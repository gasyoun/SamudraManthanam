## Письмо 1 — Д. В. Сичинаве, копия В. А. Плунгяну

**Тема:** Санскритско-русский параллельный корпус для НКРЯ — предложение и три вопроса

Дмитрий Владимирович, добрый день!

В 2020 году под Вашим руководством Е. А. Рубанова защитила в ВШЭ ВКР «Полуавтоматическая морфологическая разметка русско-санскритского параллельного корпуса»; я консультировал работу, а Владимир Александрович тогда предложил поставить санскрит рядом с хинди в разделе «Другие индоевропейские». Пишу, чтобы довести это до дела: корпус готов к передаче.

Что есть сейчас:

1. Параллельный санскритско-русский корпус «Общества ревнителей санскрита»: https://samskrtam.ru/parallel-corpus/ — Ригведа и Атхарваведа (пер. Т. Я. Елизаренковой), Махабхарата (Кальянов, Васильков, Невелева, Эрман), Рамаяна (Гринцер, Серебряный), упанишады (Сыркин) и др.
2. Выравнивание по разметке, без статистического выравнивателя: 131 текст с русским переводом, **78 219 чистых пар «стих — перевод» 1:1**; санскрит в IAST и SLP1.
3. Экспорт в трёх форматах из одного источника: XML по образцу параллельных текстов НКРЯ, TMX 1.4b и TSV. Для текстов, покрытых DCS (О. Хелльвиг, CC BY 4.0), готова морфология санскритской стороны (лемма + грамматика).
4. Слой санскритизмов для русской стороны — ровно тот класс слов, на котором, как показала ВКР, ломаются стандартные лемматизаторы.
5. Описание корпуса (статья-дескриптор, в подготовке) и сайт по ВКР с отзывами: https://gasyoun.github.io/SamudraManthanam/
6. Для сравнения: сейчас в НКРЯ русско-хинди корпус — 9 текстов, 9 490 предложений; санскрита нет.

Предлагаю начать с витрины — Ригведа, Бхагавадгита, Махабхарата III и Рамаяна I–III (те же тексты, что были в ВКР) — с проверенными библиографическими данными; остальной корпус передадим следом. Пилотный пакет прилагаю. Права по каждому тексту сведены в таблицу; решение о том, что и в каком виде включать, — за правовой рамкой НКРЯ.

Три вопроса:

1. **Формат приёма.** Какой формат сейчас принимает платформа параллельных корпусов (после перехода 2023 года)? Санскрит — в деванагари, в IAST или в обоих видах? Мы подгоним один из трёх форматов экспорта.
2. **Кто принимает.** С кем из команды НКРЯ согласовывать приём текстов и метаданных (переводчик, дата перевода, дата создания оригинала, сфера)?
3. **Лимит API.** Мы пользуемся API НКРЯ для словаря: русские соответствия в переводе санскритского словаря Бётлингка–Рота проверяем по частотам и сочетаемости НКРЯ, а не по интуиции. Сейчас ключ упирается примерно в 10 запросов в минуту. Можно ли повысить лимит для этого исследовательского проекта (например, до 60 запросов в минуту или разрешить ночные пакетные прогоны)? Все ответы у нас кэшируются, повторных запросов нет.

Буду рад созвониться в удобное время.

С уважением,

## Письмо 2 — техническая поддержка API НКРЯ (короткое, если есть отдельный адрес)

**Тема:** Просьба о повышенном лимите запросов к API — исследовательский проект

Добрый день!

Я использую API НКРЯ (word-portrait и lex-gramm concordance) в исследовательском проекте: перевод на русский санскритского словаря Бётлингка–Рота (Petersburger Wörterbuch). Каждое спорное русское соответствие проверяется по частоте (ipm) и сочетаемости в НКРЯ; результаты идут в карточки для ручной проверки редактором.

Сейчас после примерно 10 запросов в минуту API отвечает HTTP 429 (Too many requests). Для проверки словника (оценочно — десятки тысяч лемм) это растягивается на много суток.

Прошу, если возможно:

1. повысить лимит для моего ключа (например, до 60 запросов в минуту), или
2. разрешить пакетный прогон в ночные часы с более высоким лимитом.

Все ответы кэшируются локально: каждое слово запрашивается один раз, скачивания текстов нет. Готов сообщить любые данные о проекте.

С уважением,
