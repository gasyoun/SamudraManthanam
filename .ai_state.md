## 🧠 Dev Notes & Hypotheses

- `GET /api/search/context` queries `corpus_lines` by `line_num BETWEEN ? AND ?`. If a source has non-contiguous line numbers (gaps from ingest), context may return fewer lines than requested — this is correct behaviour, not a bug.
- The anchor permalink (`/sources/{id}/anchor/{link_id}`) uses a 302 redirect. If `link_id` contains URL-special characters (slash, hash), the client must percent-encode them. Corpus link_ids observed so far are dotted integers (`1.10`) — safe.
- Search permalink restores source filter from `src=1,2,3` in the URL. If sources change between sessions (re-ingest changes IDs), old permalink source filters silently deselect missing IDs. A future improvement is to filter by filename instead of ID.
- `state.db` is opened fresh per-request (no connection pool). Acceptable at current scale; watch for write serialisation under concurrent correction submissions.
- `ADMIN_SECRET_KEY` defaults to `""`. In production, if unset, `/api/admin/vacuum` and `/api/corrections/pending` are permanently inaccessible. A startup warning log when `APP_ENV == "production"` and `ADMIN_SECRET_KEY` is empty would help operators.
- `source_view.html` uses `| safe` on `line_html`. Safe only while `line_html` is exclusively ingest-produced. If corrections ever write back to corpus lines, this assumption must be re-examined.
