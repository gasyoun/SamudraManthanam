## 🧠 Dev Notes & Hypotheses

- `expand_word` opens two short-lived `aiosqlite` connections per call (read, then write). Acceptable for the infrequent morphological search path; if morph becomes a hot path, consolidate into a single connection.
- `_cache_read` / `_cache_write` silently swallow exceptions so a broken `state.db` never surfaces as a search error. The trade-off is that cache failures are invisible unless log output is monitored.
- The `live_search_url` in export metadata is a relative URL (`/?q=...`). If the export HTML is opened from a different origin, the link will break. Acceptable for a downloadable local file — users are expected to open it in a browser that has the app available.
- `GET /api/search/context` queries `corpus_lines` by `line_num BETWEEN ? AND ?`. If a source has non-contiguous line numbers (gaps from ingest), context may return fewer lines than `window` — correct behaviour, not a bug.
- The anchor permalink (`/sources/{id}/anchor/{link_id}`) uses a 302 redirect. Corpus link_ids observed so far are dotted integers (`1.10`) — URL-safe. If link_ids ever contain slashes or hashes, callers must percent-encode them.
- `state.db` is opened fresh per-request (no connection pool). Acceptable at current scale; watch for write serialisation under concurrent correction submissions.
- `ADMIN_SECRET_KEY` defaults to `""`. In production, if unset, `/api/admin/vacuum` and `/api/corrections/pending` are permanently inaccessible. A startup warning log when `APP_ENV == "production"` and key is empty would help operators.
