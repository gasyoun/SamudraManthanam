### ✅ The open-wallet exposure is closed — key funding is now a normal decision (H2866, 17-08-2026)

The old ⛔ "do not fund the OpenRouter key" block is **superseded**. Its premise
was that `/api/ai/explain` and `/api/ai/compare-translations` were publicly
reachable with no authentication and no cap — safe only because the unfunded key
answered 403, i.e. **₽75 800/day** at a sustained 10 req/s the moment anyone paid
the bill. Both halves now exist:

- **H2772** — session auth (401 without one) + hard 1 000-call/30-day quota per
  user, failing **closed** on a storage error.
- **H2866** — deny-by-default spend policy in
  [`web/app/services/ai_policy.py`](https://github.com/gasyoun/SamudraManthanam/blob/main/web/app/services/ai_policy.py):
  `AI_ENABLED` defaults **false**, `max_tokens` is bounded on every payload, and
  a worst-case per-call cost ceiling priced from `AI_MODEL_PRICES` rejects
  before any HTTP. No built-in price table, so an unpriced model fails closed.

Shipped in
[v0.19.44](https://github.com/gasyoun/SamudraManthanam/releases/tag/v0.19.44)
with `AI_ENABLED=false`, then **turned ON by operator decision 17-08-2026**
([v0.19.45](https://github.com/gasyoun/SamudraManthanam/releases/tag/v0.19.45),
[PR #322](https://github.com/gasyoun/SamudraManthanam/pull/322)). Prod journal
now reads, from both uvicorn workers:
`ai_policy: paid AI ENABLED — model=deepseek/deepseek-chat max_tokens=1024 ceiling=0.05 USD`.

The two-step design proved itself at the moment of use: the box had **no**
`AI_MODEL_PRICES` at all, so flipping only `AI_ENABLED` would have left every
call refusing `pricing_not_configured` — enabled in name, dead in practice.
`deepseek/deepseek-chat` is now priced at `0.30` in / `1.20` out USD per 1M
(OpenRouter's published `0.2574` / `1.0287`, rounded **up** so the ceiling errs
strict). Re-check that price whenever `AI_MODEL` changes; nothing in the app can
verify it, and a stale price silently widens the ceiling.

**Live money exposure:** the `0.05 USD` ceiling is per *call*, so against the
1 000-call monthly per-user quota the bound is **$50 per user per month**.
Rollback is one `sed` plus a restart —
[OPS.md](https://github.com/gasyoun/SamudraManthanam/blob/main/OPS.md)

## 🧠 Dev Notes & Hypotheses

- `expand_word` opens two short-lived `aiosqlite` connections per call (read, then write). Acceptable for the infrequent morphological search path; if morph becomes a hot path, consolidate into a single connection.
- `_cache_read` / `_cache_write` silently swallow exceptions so a broken `state.db` never surfaces as a search error. The trade-off is that cache failures are invisible unless log output is monitored.
- The `live_search_url` in export metadata is a relative URL (`/?q=...`). If the export HTML is opened from a different origin, the link will break. Acceptable for a downloadable local file — users are expected to open it in a browser that has the app available.
- `GET /api/search/context` queries `corpus_lines` by `line_num BETWEEN ? AND ?`. If a source has non-contiguous line numbers (gaps from ingest), context may return fewer lines than `window` — correct behaviour, not a bug.
- The anchor permalink (`/sources/{id}/anchor/{link_id}`) uses a 302 redirect. Corpus link_ids observed so far are dotted integers (`1.10`) — URL-safe. If link_ids ever contain slashes or hashes, callers must percent-encode them.
- `state.db` is opened fresh per-request (no connection pool). Acceptable at current scale; watch for write serialisation under concurrent correction submissions.
- `ADMIN_SECRET_KEY` defaults to `""`. In production, if unset, `/api/admin/vacuum` and `/api/corrections/pending` are permanently inaccessible. A startup warning log when `APP_ENV == "production"` and key is empty would help operators.
